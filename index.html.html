Machine Learning — Where It Lives in the Curriculum
ML is not a single course — it is a thread that builds across 5 semesters.
Sem 2
Mathematical Foundations
Linear algebra, probability theory, eigenvalues, Gaussian models — the mathematical scaffolding ML depends on.
Sem 3
Probability for Intelligent Systems
Bayesian inference, statistical estimation, regression — applied directly to sensor noise and robot state estimation.
Sem 5
AI for Autonomous Systems
Core ML: supervised learning, neural networks, CNNs, reinforcement learning basics, decision trees — taught through robotics datasets.
Sem 5
Machine Vision for Robotics
Deep learning for vision: CNN-based object detection, YOLO, semantic segmentation, transfer learning — applied to robot perception.
Sem 7
Edge AI and Deployment
Model quantisation, TensorFlow Lite, ONNX, Jetson deployment — ML models running in real-time on robot hardware.
Design principle: ML is taught the same way the curriculum handles mathematics — Just-in-Time. Students encounter probability before Bayesian estimation, linear algebra before neural networks, sensor models before SLAM. By Semester 5 they have the full ML toolkit; by Semester 7 they deploy it on real hardware.

Semester-Wise Cognitive Load —
Risk and Mitigation Framework

SemCognitive NatureLoad Level Key Risks IdentifiedMitigation Strategies
S1 Exploratory Foundations LOW · 30%
  • Students unfamiliar with engineering culture; motivation dip early
  • Robotics introduction too abstract before physical context is built
  • Programming anxiety in non-CS background students
  • Begin Sem 1 with robot demonstrations and lab exploration to inspire
  • Use Python with immediate physical outcomes (LED blink, sensor read)
  • Introduction to Robotics kept visual, story-driven, demo-rich
  • CAD taught as creative activity, not drafting exercise
S2 First Interdisciplinary Integration MOD · 42%
  • First time mechanics, electronics, and programming appear simultaneously
  • Students struggle to see how disciplines connect
  • Data Structures abstraction disconnected from physical systems
  • Unified lab: one robot kit used across electronics and fabrication practicals
  • Data Structures taught with robotics planning examples (maps, queues)
  • Mini integration project: sensor-to-display pipeline by end of semester
  • Peer learning groups organised by faculty from Sem 2 onward
S3 Abstract Embedded Thinking HIGH · 55%
  • Signals and Systems is mathematically dense — abstraction overload risk
  • OOP concepts feel disconnected from hardware for non-CS students
  • Simultaneous electronics + mechanisms + probability is heavy
  • Signals course opens with robot-relevant examples (encoder signals, sonar)
  • OOP taught by building Robot class and Sensor class — not abstract examples
  • Probability immediately contextualised: sensor noise, Gaussian error models
  • 2 labs absorb hands-on time, reducing theory pressure
S4 Control and Robotics Reasoning HIGH · 65%
  • Kinematics (DH Parameters, IK) is the first truly hard robotics mathematics
  • Control Systems (Bode, Nyquist, Root Locus) is a classic student bottleneck
  • Embedded Systems + PLC + Control simultaneously risks overload
  • Kinematics lab runs MATLAB/Python simulation — visualising DH before derivation
  • Control Systems taught with robot arm PID as the running design example
  • PLC and Embedded scheduled in different weekly slots to avoid same-week peaks
  • Design Thinking course placed here deliberately — creative relief valve
S5 Intelligent Systems Cognition ⚡ PEAK PEAK · 95%
  • RTOS + AI + Vision + Fieldbus + Machine Design all simultaneously — maximum breadth
  • Toolchain explosion: OpenCV, FreeRTOS, EtherCAT, Python/ML simultaneously
  • Vertical elective adds a 6th cognitive domain on top of 5 core courses
  • Students must suddenly think in systems, not components — cognitive mode shift
  • Machine Design revives mechanical stress analysis — context switch risk
  • Simulation-first pedagogy: all new tools introduced in virtual environment before hardware
  • Integrated lab project: one perception-to-decision pipeline spanning both labs
  • Toolchain onboarding workshops in first 2 weeks before regular class flow
  • AI course uses scikit-learn / PyTorch with robotics datasets — no pure theory
  • Machine Design scoped narrowly to robot frame and arm components only
  • Vertical elective scheduled on a separate day to prevent cognitive collision
  • Faculty coordination: AI, Vision, RTOS faculty hold joint integration seminars
  • Assessment: project demonstrations replace written exams for lab-heavy courses
S6 Autonomous Systems Integration ⚡ PEAK PEAK · 90%
  • ROS2 is a new complex ecosystem — nodes, topics, TF, Nav2, launch files
  • AMR systems require integrating everything learned in Sems 1–5 simultaneously
  • Motion control and drives introduce new hardware domain (servo drives)
  • IIoT adds cloud/edge networking layer on top of existing stack
  • System Design course demands architecture thinking — most students not ready
  • ROS2 introduction starts in Sem 5 elective (Vertical 1) — not cold start in Sem 6
  • AMR lab uses OMRON LD-250 on CoFact floor — real platform, not only simulation
  • System Design course uses previous semesters' robot as the design subject
  • IIoT taught through CARR Lab's live sensor-to-dashboard pipeline
  • Scaffolded learning: each course builds toward a shared Sem 6 capstone demo
  • Peer teaching: Sem 6 students mentor Sem 4 students on PID and kinematics
  • Assessment: integration-based rubrics — not recall; partial credit for debugging
S7 Industrial Specialisation MOD · 60%
  • Major Project Phase I is open-ended — some students lack problem definition skills
  • Entrepreneurship course feels non-technical to engineering-focused students
  • Transition from structured coursework to self-directed project is a challenge
  • Major Project topics shortlisted and pre-approved by Week 2 with faculty guidance
  • Entrepreneurship contextualised through CARR Lab spin-off and startup case studies
  • HRI and Safety course includes live OMRON TM5 collaborative demo
  • Monthly project reviews with industry mentor panel from CARR Lab network
S8 Professional Synthesis LOW · 40%
  • Internship + Major Project simultaneously can create time management failures
  • Ethics and Standards course perceived as non-core by some students
  • Research Methodology has low engagement without immediate research context
  • Internship and Major Project timelines formally coordinated — no overlap in crunch periods
  • Ethics woven around real autonomous vehicle, drone, and AI liability case studies
  • Research Methodology directly tied to Major Project Phase II report writing
  • Internship seminar includes alumni panel from previous batches — peer inspiration
